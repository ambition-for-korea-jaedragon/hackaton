# /ship — 외부에서 실제로 쓰이는 후보

context/spec/plan과 행사 규칙을 읽는다. 배포 서비스는 **spec의 기술 선택**을 따른다. 선택이 없으면 필요한 조건부터 정하며 특정 서비스를 기본값으로 설치하지 않는다.

1. 대상 계정·프로젝트·권한·비용과 실행 계약의 절차를 확인한다. 필요한 비밀은 배포 환경에 별도 등록한다. 로컬 설정만으로 전달됐다고 간주하지 않는다.
2. 공유 변경 후 명시된 검사·테스트·필요한 빌드를 실행한다. 대상 후보를 커밋·main push하고 원격 SHA를 확인한다.
3. 선택한 방식으로 배포하고, 실제 외부 기기 또는 독립 세션에서 제출 URL을 연다. 접근에 계정이 필요하면 심사용 접근 수단을 준비한다.
4. 제출할 사용법으로 입력→결과를 수행한다. AI·외부 연동은 실제 호출과 실패 경로를 나눠 검증한다. URL 응답만으로 성공을 주장하지 않는다.
5. 유지 담당과 기한·크레딧·비용·프로세스 유지 조건을 확인한다. 제출 후보의 URL·내용이 후속 작업으로 바뀌지 않게 한다.

자동 브라우저 도구가 없다면 사람이 동일 시나리오를 수행해 증거를 남긴다. 특정 검사 스크립트의 설치를 필수로 만들지 않는다. 초기 환경 점검에서는 확인한 부분과 미구현 부분을 구분한다.

완료: 외부 접근·핵심 시나리오·유지 계획이 검증됐고 URL·커밋·시각이 spec/plan에 있다. 제출 후보가 바뀌면 덱·사용법도 함께 갱신한다.
