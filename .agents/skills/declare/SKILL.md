# /declare — 주제와 공개 레포 등록

최종 제출과 다른 단계다. `docs/hackathon.md`, `docs/context.md`, `docs/ideas.md`를 읽는다. 목표 10:25 완료, 공식 마감 **10:30 KST**.

## 새 레포

`TZ=Asia/Seoul date`, 현재 폴더·remote·브랜치를 확인한다. 제품 코드는 공지된 시각 이후 작성한다.

새 폴더에서 세션을 시작하거나 작업 기준을 명시적으로 전환하고, 이후 읽기·쓰기·셸이 모두 새 레포를 대상으로 하는지 확인한다. 도구 선택·설치는 다음 spec/scaffold 단계에서 한다. 앱 생성·배포 서비스 결정을 선언의 선행 조건으로 삼지 않는다.

GitHub owner/이름은 context 값을 사용한다. 새 레포가 이미 있으면 그대로 검증하고 중복 생성하지 않는다. 새 repo 생성·push가 승인된 작업 흐름 안이라면 메인이 수행한다. 기존 remote가 다른 프로젝트면 덮어쓰지 말고 올바른 새 폴더로 이동한다.

첫 push 전 staged 파일과 diff를 점검하고 키·환경 파일이 없는지 확인한다. `gh repo view --json url,visibility,defaultBranchRef` 등으로 **PUBLIC·main·원격 커밋**을 확인한다. 비밀 값은 로그로 출력하지 않는다.

## 선언

https://ambition-for-korea.vercel.app/submit 에서 팀을 찾는다. 신청 이메일, 또는 팀 이름+팀원 이름으로 확인한다. 주제·아이디어·타깃 해외 시장·공개 레포 URL을 준비해 사용자가 등록하게 한다. 사용자가 브라우저 대행을 요청한 경우 주제 선언 버튼만 실행한다.

현재 폼은 선언 마감 전 수정 기능을 제공한다. 수정 가능 여부는 실제 화면을 확인한다. 최종 제출 버튼을 주제 선언으로 착각하지 않는다.

완료: 공개 레포 URL·main 커밋·선택 주제·**선언 완료 시각/화면 확인**이 context에 있다. 폼이 닫혔거나 팀 조회가 실패하면 즉시 운영진에게 알려 해결하며 완료로 표시하지 않는다. 다음은 `/spec`.
