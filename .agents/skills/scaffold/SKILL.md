# /scaffold — 선택된 환경 준비

context/spec/plan을 읽는다. **주제·결과·기술 선택·실행 계약이 선행 조건**이다. 없으면 `/spec`으로 돌아간다. 특정 생성기를 기본값으로 실행하지 않는다.

1. 실제 작업 폴더·새 공개 remote·main·제품 작성 허용 시각을 확인한다.
2. 선택한 기술의 지침과 기존 파일을 읽는다. 실행 계약의 초기화·의존성 설치를 수행한다. 해당 기술의 의존성·생성물·로컬 설정에 맞게 ignore 규칙을 갱신한다. 새 폴더에서는 필요한 도구가 실제 설치돼 있는지 확인한다.
3. 이미 초기화된 환경은 검사하고 재개한다. 생성기 실행 전에 앱 폴더나 비밀 파일을 미리 만들어 충돌시키지 않는다.
4. 최소 실행을 먼저 확인한다. 필요한 비밀은 초기화 후 해당 환경의 안전한 저장 방법으로 등록하고 로컬·배포 설정을 구분한다.
5. 제품에 맞는 실행·검사를 수행한다. 가능한 이른 시점에 외부 접근 경로도 점검하되, 복잡한 배포가 핵심 위험 검증을 막으면 두 작업을 분리한다.

선택한 절차의 cwd·버전·성공 결과를 spec/plan에 남긴다. 초기 화면·출력이 뜬 것과 핵심 시나리오 완성은 구분한다.

완료: 최소 환경이 기록된 절차로 재현되고 선택한 기술의 검사가 통과했다. 다음은 `/dispatch`.
