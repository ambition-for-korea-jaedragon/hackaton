# /dispatch — 구현 라운드

context/spec/plan과 runbook을 읽고 현재 시각·남은 시간·마지막 검증 후보를 갱신한다. 기술 결정·실행 계약이 비어 있으면 먼저 spec을 채운다. 기능 동결 시점이면 제출 결함만 고친다.

## 배정

선행 조건이 끝난 작업 중 서로 독립된 것만 병렬로 배정한다. 필요한 의존성·공유 계약은 메인이 먼저 준비한다. 공유 기초 작업은 한 명에게 독점 배정한다.

```
Goal: 사용자에게 필요한 결과
Spec: 해당 요구·행동→결과·검증 기준
Owned files: 선택한 소스 루트 기준의 정확한 경로
Inputs / outputs: 합의한 데이터·인터페이스 계약
Constraints: 선택한 기술·버전·참고 문서·사용 환경
Do not touch: 다른 소유자의 파일과 공유 자원
Done: 구현 완료와 해당 작업에서 실제 확인할 조건
Report: 변경 파일·확인 결과·미검증·공유 변경 요청
```

역할·모델은 AGENTS의 정의를 따른다. 긴 구현은 builder, 카피·근거 정리는 writer, 조사는 scout, 검증은 qa에 맡긴다. 하위 작업의 done에 병렬 전체 빌드를 넣지 않는다.

## 통합

1. 모두의 변경·공유 요청을 검토하고 메인이 필요한 공유 변경을 반영한다.
2. 실행 계약의 검사·테스트·필요한 빌드를 직렬 수행한다. 서버·작업 프로세스가 있으면 새 후보를 실제 실행하도록 관리한다.
3. qa에 후보·접근 방법·사용자 시나리오·기대 결과를 준다. 반복 실행·복구·실패를 포함한다. 자동화 수단이 없으면 사람이 관찰하고 미검증 부분을 명시한다.
4. 실패는 원문·재현 단계로 해당 소유자에게 돌린다. 같은 오류가 반복되면 runbook의 중단·축소 기준을 따른다.

관련 파일만 stage하고 비밀·불필요한 산출물·diff를 점검한다. 검증된 후보를 main에 커밋·push하고 원격 SHA를 확인한다. plan에 명령·cwd·시각·결과를 남긴다. 원격 충돌은 force로 덮지 않는다.

완료: 통합된 요구가 실행 계약과 실제 시나리오를 통과하고 main에 반영됐다. 핵심 결과·근거는 덱 담당자에게 넘긴다.
