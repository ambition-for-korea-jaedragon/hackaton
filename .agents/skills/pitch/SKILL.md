# /pitch — 주장과 증거

spec/context/evidence를 읽고 행사 규칙·[공식 키트](https://ambition-for-korea.vercel.app/kit/)의 형식을 따른다. 초안은 고객·결과를 정한 직후, 최종 화면·URL은 배포 후 반영한다. 특정 앱 스택이나 덱 제작 도구를 전제하지 않는다.

writer 브리프: goal(고객 가치와 오늘 만든 결과를 공식 두 장에 설명) / owned files(`docs/pitch/deck.md`와 선택한 제작 파일) / done(아래 내용·근거·형식).

- 1장: 서비스·한 줄 소개, 구체 해외 고객, 문제, 선택 주제.
- 2장: 실제 제품 화면·결과, 어떻게 동작하는지, Claude를 어디에 썼는지. 실측·추정·sample을 구분한다. 팀 적합성·다음 7일은 공간이 있을 때.
- 숫자·고객·절감률의 출처와 관찰 조건은 deck.md에 기록한다. 개발 마일스톤을 고객 수요라고 부르지 않는다.

현재 후보를 실제 사용한 뒤 결과 화면을 캡처한다. 공식 키트의 페이지 수·비율·글자·로고 규칙을 적용한다. 제작 도구는 팀이 사용 가능한 것으로 고르며 새 의존성 설치가 필수는 아니다. 공식 HTML 템플릿을 쓰면 브라우저 인쇄로 PDF를 만들 수 있다.

PDF와 각 장을 직접 열어 잘림·가림·가독성·공식 로고·실제 화면·URL을 확인한다. 낯선 팀원이 무슨 제품인지 설명할 수 있는지 본다.

제출 PDF를 먼저 끝내고 영어 발표 원고·한국어 Q&A를 준비한다. 공식 시간에 맞춰 실제로 소리 내어 잰다. 발표 연습 때문에 제출 가능한 후보를 늦추지 않는다.

완료: 행사 요건을 만족하는 PDF가 현재 제출 후보와 같은 주장·근거·URL을 담고 있다.
