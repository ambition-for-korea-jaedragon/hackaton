# /submit-check — 제출 후보 판정

context/spec/plan과 `docs/hackathon.md`를 읽는다. 목표 시각·남은 자리를 확인하고 준비된 후보는 기다리지 않는다.

## 제품·실행

- 주제·공개 레포 선언 완료가 기록돼 있다.
- 새 레포 PUBLIC, main 원격 SHA와 검증 후보가 일치하고 제품 작성 시각이 규칙에 맞다.
- 공개 파일·산출물·클라이언트에 실제 비밀 키나 허가되지 않은 데이터가 없다.
- 통합 후 **spec 실행 계약의 검사·테스트·필요한 빌드**가 통과했다. 해당 없는 단계는 이유·대체 증거가 있다.
- 실제 제출 URL과 필요한 심사용 접근 수단으로 사용자 행동→결과·반복·복구가 확인됐다.
- 사용한 AI·외부 연동은 실제 성공과 실패 경로가 각각 검증됐다.
- 선택한 사용 환경에서 필요한 조작·결과가 보인다. URL 상태 검사나 정적 설정 검사만으로 완료 처리하지 않는다.

## 제출 담당자

- 작성자의 추가 설명 없이 팀원이 **제출할 사용법 3줄만** 보고 핵심 시나리오를 재현했다.
- 실측·외부 사실·추정·sample 표시와 덱의 근거가 일치한다.
- PDF와 데모가 같은 후보이며 공식 키트의 페이지·비율·로고·내용 조건을 충족한다.
- 공지된 기한까지 URL·계정·키·프로세스·비용을 유지할 담당이 정해졌다.

## 접수

`docs/submission.md`에 행사 규칙과 실제 폼의 필드를 대조해 공개 가능한 제출 패킷을 만든다. 서비스·소개·타깃·주제·레포·데모·3줄 사용법·PDF·오늘 만든 부분·검증 SHA·유지 담당을 담는다. 필요한 테스트 계정은 데모 전용이며 실제 키·신청 이메일을 공개 문서에 적지 않는다.

필수 검증이 끝나면 제출 담당자가 공식 페이지에서 최종 제출한다. UI 대행은 사용자가 지시한 범위에서만 한다. 팀 조회·선언·업로드를 접수 성공으로 착각하지 않는다.

완료: 접수 확인·시각·URL·PDF·main SHA를 기록했다. 응답이 불명확하면 상태부터 확인하며 중복 제출하지 않는다. 제출한 버전은 보존한다.
