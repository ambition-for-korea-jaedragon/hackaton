# /interview — 시작 정보

`docs/hackathon.md`, `docs/runbook.md`를 먼저 읽는다. 확정된 행사 요건은 다시 질문하지 않는다.

1. 미션 원문을 받아 `docs/mission.md`에 보존한다.
2. 팀·역할·활용 가능한 경험·시간을 확인한다. 구현·통합 담당과 증거·제출 담당을 정한다.
3. 행사 계정·조직과 크레딧 사용 상태를 확인한다. 로그인·청구 경로가 다를 수 있으므로 실제 계정 출처를 확인하되 키 값은 기록하지 않는다.
4. GitHub 접근과 새 레포 소유자, 유지 담당을 확인한다. 배포 계정은 사용 가능한 후보만 기록하며 특정 서비스를 선택하지 않는다.
5. 주제 선택에 필요한 부족한 정보만 한 묶음으로 질문한다.

`docs/context.md`: 팀·역할 / 경험·제약 / 주제 원문 위치 / 행사 계정 확인 상태 / 새 레포 소유자·URL / 목표 제출 시각 / 유지 담당 / 선언 상태 / 남은 결선 자리·확인 시각. 신청 이메일은 공개 문서에 남기지 않는다.

제품 AI 필요성·키 저장 위치·런타임·앱 형태는 주제와 기술 선택 후 정한다. 이 단계에서는 제품 폴더나 환경 파일을 만들지 않는다.

완료: 주제 원문과 팀의 실행 조건이 기록됐다. 다음은 `/ideate`.
